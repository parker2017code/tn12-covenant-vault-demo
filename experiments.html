Why this is useful

The point is money with visible rules.

A normal server can track a game, budget, or payout rule. These experiments ask a harder question: can the spend itself carry the rule so the money only moves through accepted, replayable paths?

Plain level

Budgets, games, assets, and group payments become easier to trust when users can see which moves worked and which moves were refused.

Technical level

Covenant IDs, continuation outputs, sibling inputs, mux routing, and timeout paths let small UTXO scripts compose without one shared app database.

Kaspa angle

Fast TN12 UTXO flow makes multi-transaction state machines practical enough to inspect as workflows, not only as slow settlement events.

Three strongest demos

Best fit for Kaspa's edge.

1 Blitz Mux Arena

A hub covenant routes state to Worker A, Worker A returns state to the hub, then a fresh pending worker times out back to the hub.

This points toward turn-based games, disputes, staged approvals, and workflows where each step chooses the next bounded role.

  • Mux / worker contract family.
  • Template routing.
  • Accepted TN12 family genesis output.
  • Accepted route to Worker A.
  • Accepted Worker A return to mux.
  • Accepted Worker A timeout return to mux.
2 Treasury Wars

Players spend from capped treasuries. The accepted TN12 path now proves two cumulative spends, a reset-window spend, continuation state, and relocked change.

This points toward allowance wallets, team treasuries, merchant payout limits, grant streams, and app resources where rules travel with the funds.

  • Active RecurringTreasuryVault.sil rail.
  • Reset branch in RecurringTreasuryVaultWindow.sil.
  • Accepted covenant-genesis funding output.
  • Two accepted under-cap covenant spends.
  • Accepted reset-window covenant spend.
  • Over-cap continuation candidate blocked locally.
  • Early, stale-window, and over-cap reset candidates blocked locally.
3 Covenant-Owned Asset Duel

An asset move requires the owner-marker covenant input in the same transaction. The accepted strike uses sibling authority instead of nested execution.

This points toward tickets, passes, game items, licenses, and app-owned assets that move only when the controller path is present.

  • ICC / sibling-input authorization.
  • Accepted owner-marker covenant output.
  • Accepted live asset-duel covenant output.
  • Accepted two-input sibling-authorized strike.
  • Live-id local rejects for wrong witness, missing sibling, and wrong sibling id.

Treasury Wars track

One budget window, one reset, three blocked resets.

The simple story is allowance with rules attached to the funds. The technical story is stateful covenant continuation: spend under cap, carry state forward, reject the over-cap move, then open a new window through a reset branch.

Asset Duel round

One controlled asset, one sibling authority.
