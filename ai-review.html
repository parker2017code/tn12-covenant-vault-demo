Reviewer rules. Public and LLM-facing.

Do not turn evidence into a bigger claim.

TN12 evidence is useful because it is specific: txids, scripts, artifacts, replay rows, local-wallet policy, and exact blockers. Keep those classes separate.

Short rule Accepted is not mainnet. Wallet policy is not script enforcement.

Use the label that matches the evidence.

Claim labels

Use the exact bucket.

1 TN12_ACCEPTED

A transaction or payload event landed on Kaspa testnet-12 and the repo can point to the txid, endpoint response, fixture, or artifact.

2 SCRIPT_ENFORCED

The SilverScript spend path enforces the named rule. Do not use this for reducer checks, local-wallet refusal, or planner state.

3 WALLET_POLICY

A wallet, signer, operator, or local builder refuses or allows the action before broadcast. Useful, but not the same as covenant enforcement.

4 INDEXER_DERIVED

Replay or reducer logic derives app state from accepted rows. It explains state; it does not control funds by itself.

5 MAINNET_BLOCKED

Useful testnet or local evidence exists, but mainnet activation, wallet signing, custody review, audit, or production replay is missing.

6 RESEARCH_ONLY

Architecture, game idea, coordination pattern, or source-derived design note. Build a contract, artifact, test, and evidence row before upgrading it.

Kaspa context

How AI should talk around Kaspa here.

Explain
  • Fast mined ordering.
  • UTXO covenant spend rules.
  • Accepted testnet evidence.
  • Replayable app state.
Separate
  • Mainnet Kaspa behavior.
  • Toccata/TN12 testnet behavior.
  • Wallet-policy and local-key tests.
  • Research ideas from KIPs, Silverscript, and chess examples.
Avoid
  • Calling testnet proof a mainnet product.
  • Calling planner rows custody.
  • Calling txids alone contract depth.
  • Using vague adoption or readiness language.

SilverScript build lessons

Do not build shallow wrappers when the target is covenants.

1 State is the point

Recurring caps, assets, and game state should use explicit state, continuation outputs, and `validateOutputState` where the compiler supports it.

2 Covenant IDs are lineage

Use covenant IDs to track family membership. Use template hashes and state fields for role identity inside a closed contract system.

3 Use mux / worker for complex logic

A hub can route to small worker contracts, and workers can return to the hub. This avoids one giant script and fits fast multi-transaction flows.

4 Use ICC for authority

Do not try to execute arbitrary contracts inside a contract. Let sibling inputs prove that another covenant or script authorized the transaction.

5 Challenge beats global scanning

For expensive absence proofs, let one party make a claim and give the other party a bounded challenge path. Timeouts keep the system live.

6 Negative cases are part of the demo

Wrong signer, wrong destination, over cap, missing continuation, stale window, and missing sibling input are the checks that make the example serious.
